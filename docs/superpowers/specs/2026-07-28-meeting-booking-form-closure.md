# 会议预约完整表单闭环

## 范围

本次补齐租户小程序会议预约表单，并同步服务端保存、模块字段 Schema 与后台展示。会议室资产只提供可预约资源与收费依据；预约事实仍由会议模块保存，是否形成财务账单继续由既有资产计费依据与财务链路决定。

## 字段与数据来源

| 字段 | 小程序行为 | 服务端规则 |
| --- | --- | --- |
| 租户申请来源、申请人、企业、身份手机号 | 只读展示，手机号掩码 | 从当前移动身份解析，拒绝客户端覆盖 |
| PUBLIC 游客申请人、联系电话 | 可编辑必填；联系电话支持大陆手机或固话 | 仅保存本次预约回拨快照；不参与身份匹配、租户绑定或 capability 授权 |
| 部门 | 不采集、不提交 | V57 可空字段仅保留后台及历史兼容 |
| 会议用途 | 必填，最长 255 字 | 必填并由 Schema 再校验 |
| 参会人数 | 必填正整数 | 不得超过会议室容量 |
| 会议室、开始/结束时间 | 先选会议室，再滑动确认时间并显示空闲/占用 | 预检后仍校验未来时间、正向区间和时段冲突 |
| 收费依据 | 只读展示 | 按现有会议收费规则计算和保存快照 |
| 备注 | 可选，最长 500 字 | 保存到既有 `remark` |
| 动态扩展字段 | 使用公共动态表单 | 按 `meeting_booking` 模块 Schema 校验和保存 |

## API 与权限

- 继续使用现有租户会议接口，并复用 `GET /mobile/public/meeting-rooms/{roomId}/availability` 做指定房间和时段预检；不新增客户端身份接口。
- 租户创建预约时，客户端不得提交 `tenantId`、`mobileUserId`、`contactName` 或 `contactPhone`。PUBLIC 游客可提交 `contactName/contactPhone` 业务快照，但不得提交任何租户、移动用户或申请人关系 ID。
- PUBLIC 游客必须先有微信官方已验证手机号并取得 `meeting.guest.book` capability。服务端再次校验手工联系电话；未填写时兼容回退到微信已验证手机号，但绝不使用手工号码更新 `mobile_user`、匹配租户或改变 principal。
- 预约列表与详情按当前身份限定租户和本人范围；其他租户访问返回 404。
- 后台继续使用既有会议管理权限，V57 不增加或放宽 RBAC 权限。

## 移动端房间优先交互

- 页面顺序固定为“最近预约 → 默认展开的会议室 → 已选房间 → 日期和开始/结束时间 → 预约表单”。预约模式只展示最近两条记录和“查看全部”，避免完整历史继续拉长预约路径。
- 房卡不能使用页面初始默认时段的 `available` 值禁止进入。用户先选房，再通过日历和滚轮确认时间；每次确认后就地显示检查中、空闲、占用、时间无效或查询失败。
- 预检前先按房间 `openTime/closeTime` 判断开放时段；请求使用递增序号及 `roomId|date|start|end` 键隔离连续滑动产生的旧响应。只有当前键确认空闲时提交按钮才启用。
- 租户的申请来源、申请人、企业与掩码身份手机号使用只读摘要；PUBLIC 游客的申请人和本次联系电话直接可编辑，并明确手工号码不用于业务身份匹配。会议用途和参会人数直接可见，小程序不显示部门。备注及可选动态扩展字段默认折叠，必填扩展字段或校验失败时自动展开。
- PUBLIC 游客未完成微信手机号身份验证时，表单底部显示可操作的“验证手机号并继续”，不得只显示禁用按钮导致用户需要回到页面顶部寻找授权入口。
- 选择时间时保留已选会议室；“更换”只清除房间和可用性状态，保留时间便于快速改选。全量刷新同时使旧可用性请求失效，不得产生幽灵选中。
- 提交前端门禁只提供即时反馈；后端创建预约仍在事务内锁定会议室并重新检查重叠，处理预检后被其他用户抢占的竞态。

## 会议室详情与图片展示

- 管理后台会议室卡片采用左摘要、右媒体布局。摘要包含名称、位置、容量、可预约状态、设施、开放时间、参考费率和今日预约数；右侧有图时通过受保护文件 Blob 展示，无图或加载失败时回退设施、说明和开放时间。右上角管理入口使用 26×26 半透明深色圆形菜单，避免白色悬浮块遮挡图片。
- 会议室编辑弹窗复用公共 `CustomFieldValueInput`。受保护 `/api/files/*` 图片必须由统一请求层携带 Authorization 下载为 Blob/Object URL 后再交给图片组件；不得直接绑定受保护 URL。加载失败显示稳定占位，数据变化和组件卸载时回收 Object URL。
- 小程序公共列表、可选会议室和已选会议室摘要使用同一组展示字段：位置、容量、设施、说明、开放时间和图片。图片错误会切换到详情回退，不保留空白媒体区。
- 已认证后台和移动端继续通过原有权限链路读取内部图片信息。PUBLIC `/mobile/public/meeting-rooms` 只返回 `images[].url` 与 `coverImageUrl`，不返回 `imageFileIds`、文件 ID、文件名、MIME 或大小，也不返回费率；游客预约成功响应只返回预约总金额，不返回 `unitPriceSnapshot`。
- PUBLIC 图片使用 `/mobile/public/meeting-rooms/{roomId}/images/{fileId}`。服务端要求图片属于指定会议室、`meeting-rooms` 工作区、允许的会议室图片业务类型、`INTERNAL` 访问范围、启用且未删除，并限制为 JPEG/PNG/WebP 和真实上传目录内文件。
- 会议室图片属于资产基础数据展示，不直接产生财务账单；预约费用仍按既有收费规则由服务端计算并保存快照。
