# DHIC 系统管理简化闭环差异矩阵

## 产品边界

| 对象 | 唯一维护入口 | 权限来源 |
| --- | --- | --- |
| 物业内部员工 | 系统管理 / 用户管理 | `sys_user -> sys_user_role -> sys_role_permission` |
| 角色权限 | 系统管理 / 角色管理 | 模块读写权限包展开为现有细粒度 permission code |
| 微信身份 | 系统管理 / 小程序用户 | 已验证手机号计算出的合法业务身份 |
| 租户负责人、租户员工 | 租户管理 / 租户档案 / 联系人 | `tenant_contact`，不进入 `sys_role` |

## 实施前差异

| 范围 | 已有能力 | 本轮缺口 | 本轮处理 |
| --- | --- | --- | --- |
| 系统菜单 | 用户、角色、小程序用户三个入口已存在 | 展示顺序不一致 | 固定为用户、角色、小程序用户 |
| 用户管理 | `sys_user`、角色、移动开关、绑定状态 | 仍展示租户用户类型；强制用户名密码；缺后台登录开关、主要角色和最后登录 | V51 增加后台登录、主要角色、最后登录；表单只维护内部员工 |
| 角色管理 | 模块读写权限包、部分历史权限保留、菜单同步 | 缺移动模块提示；普通管理员可尝试授予超出自身的权限 | 显示六项移动映射；服务端限制新增授权范围 |
| 小程序用户 | 微信自动创建、手机号匹配、多身份与默认身份 | 管理接口仍允许任意 tenantId 手工绑定；缺状态、详情和审计闭环 | 移除任意业务 ID 绑定，改为服务端候选、默认身份、停启用、解绑和审计 |
| 租户联系人 | 负责人/员工、主联系人、状态和手机号登录提示 | 缺职位；原主联系人角色可能未同步降级；手机号变化未主动标记重验 | V51 增加职位；保存时统一主联系人并使旧绑定进入重验 |
| 权限实时性 | 后端每次请求刷新角色/permission；移动身份每次刷新 | ADMIN 菜单仍有全菜单短路 | 仅 SUPER_ADMIN 全菜单，ADMIN 按数据库菜单 |
| 自保护 | 系统角色禁用/删除保护 | 用户自停用、自删除、最后 SUPER_ADMIN、系统角色类型和越权授予保护不完整 | 后端事务内校验并拒绝 |

## 兼容原则

- 不修改 V1-V50，不删除历史用户、角色、permission 或移动绑定。
- 历史角色未触碰的部分 permission 原样保留；明确勾选时才展开或移除模块权限包。
- 历史后台用户默认允许后台登录；历史主角色从当前有效角色中确定，不改变原有角色关系。
- 解绑只停用关系并追加审计，不物理删除绑定。
- 小程序继续只在用户主动手机号授权时调用微信能力；退出后的本地 PUBLIC 行为不变。
