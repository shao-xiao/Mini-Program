# 会议预约物业审核与回复闭环

## 业务状态机

```text
提交预约
→ PENDING
→ CONFIRMED（审核通过）
  或 REJECTED（审核驳回）
```

- 新预约不再以 `BOOKED` 表示成功；历史 `BOOKED` 仅作为待审核兼容输入。
- 只有 `CONFIRMED` 占用会议室时段并进入完成流程。
- `REJECTED` 不占用时段、不生成收费依据，也不能再取消、完成或重复审核。
- 审核通过时才复用现有会议收费规则创建收费依据；会议模块不自行创建财务账单。

## 接口与权限

- `POST /api/meeting-bookings/{id}/confirm`：审核通过，可选提交 `reviewReply`。
- `POST /api/meeting-bookings/{id}/reject`：审核驳回，`reviewReply` 必填。
- 两个操作均复用既有 `meeting-booking:confirm` 权限；`AuthInterceptor` 不按角色名称放行。
- 审核人来自当前服务端 principal，客户端不能提交 `reviewedBy`、`tenantId`、`mobileUserId` 或其他关系 ID。
- Controller/Service 继续校验预约状态和会议室时段；权限通过不代表可以跳过状态机。

## 数据与迁移

V62 为 `meeting_booking` 追加：

| 字段 | 含义 |
| --- | --- |
| `review_reply` | 物业审核回复，最长 500 字 |
| `reviewed_by` | 审核后台用户，由服务端写入 |
| `reviewed_at` | 审核时间，由服务端写入 |

迁移不更新历史预约、不修改 V61 及以前文件。历史 `BOOKED` 可由审核入口平滑处理。

## 前端契约

- 管理后台预约工作台在待审核记录上显示“审核”，弹窗选择通过或驳回并填写回复。
- 详情和表格显示审核状态、物业回复、审核人、审核时间。
- 小程序预约记录显示“待审核 / 审核通过 / 已驳回”及物业回复；会议详情必须将物业回复作为独立审核区显示，保留后台换行，并同时标明预约编号和审核时间，不得仅混入普通键值表。
- 小程序预约首页只突出服务端排序后的最新一条预约进程；存在历史记录时用卡片堆叠提示并保留“查看全部”。取消预约属于详情级危险操作，不得在摘要卡中作为醒目主操作展示。
- 可用性查询、工作台摘要和统计排除 `CANCELLED`、`REJECTED`；小程序不自行推导审批结果或费用。
