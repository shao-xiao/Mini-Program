# 工单中文详情、照片与历史记录闭环

日期：2026-07-30

## 目标

- 租户小程序工单详情不再显示英文字段名、英文枚举或对象 JSON。
- 报修原图、后台字段补充图、处理过程图分别展示，不混并、不重复。
- 多条报修历史采用堆叠预览，右上角提供“查询历史记录 / 收起历史记录”。
- 后台详情和受保护照片执行相同的负责人数据范围，禁止仅有查看权限的账号通过直链越权。

## 小程序展示规则

`pages/business-detail` 对 `type=workorder` 使用专用展示适配器：

- 核心字段统一为中文标签；兼容 `orderNumber/code`、
  `category/problemCategory`、`reporterPhone/contactPhone`、
  `reporterName/contactName`。
- 工单类型、问题类型、优先级、状态和处理动作转换为中文业务文案。
- `attachments`、`images`、`records`、`customFields` 不进入通用详情行，
  页面不再渲染原始 JSON。
- 页面先呈现中文字段和图片占位，再以最多 4 个并发任务把受保护图片鉴权下载到
  微信临时路径；图片或文档附件不会持续写入用户数据目录。
- 统一请求模块只向当前 API 同源地址发送登录 `Authorization`；历史外链图片仍可
  下载，但不会携带当前会话令牌。
- 多选和布尔自定义字段分别使用后台中文选项与“是/否”，XLS/XLSX/PPT/PPTX
  附件按真实格式打开，未知文档类型不再强制伪装为 PDF。

照片按业务来源独立呈现：

1. “报修现场照片”：提交报修时的基础图片。
2. “补充信息”：后台字段平台中的图片字段，标题使用服务端中文字段名。
3. “处理记录照片”：某条处理记录产生的过程图片，跟随该条记录展示。

工单 `12` 的真实数据验证为：基础图片 `file_id=36`、补充图片
`file_id=37`、处理图片 `file_id=38`，三组均只出现一次并可鉴权预览。

## 历史记录规则

- 报修页默认显示多条记录的堆叠预览；首条展示完整摘要，其余记录作为下层卡片。
- 右上角显示“查询历史记录 · N 条”；点击后展开全部卡片，再次点击收起。
- 工单详情中的处理历史按时间倒序展示动作、处理人、时间、内容和该步骤附件。
- 隔离验收记录 `WO-7E42E841DA4E`、`WO-DD4EED94ACF4` 与既有工单
  `WO-08E154D53A23` 构成三条历史，用于最终人工检查堆叠和展开状态。

## 权限与文件边界

- `GET /api/workorders/{id}` 接收服务端 `AuthPrincipal`。
- 后台工单列表和详情自身显式要求 `workorder:view`（或模块/全局通配、
  `SUPER_ADMIN`），不依赖外部拦截器才能守住查看权限。
- 拥有 `workorder:assign`、`workorder:*`、`*` 或 `SUPER_ADMIN` 的账号可查看全部工单。
- 只有 `workorder:view` 的后台账号仅可查看 `assignee_id` 为自己的工单；
  不存在或越权统一返回 404。
- `/api/files/{id}` 对 `WORK_ORDER` 以及
  `workspace_key=workorders` 的 `CUSTOM_FIELD` 文件复用同一负责人范围，
  不允许回退到仅工作区权限校验。
- 尚未绑定业务记录的 `CUSTOM_FIELD_IMAGE/CUSTOM_FIELD_ATTACHMENT` 草稿仅允许
  上传者读取；绑定工单后再按工单负责人或租户范围读取。
- 租户端继续按服务端租户、本人或租户管理员范围读取，客户端不能提交或伪造租户、
  提交人、负责人和权限字段。

本次未新增 Migration，Flyway 仍为 V62；没有修改工单状态机或已有接口返回契约。

## 数据模型边界

基础报修图片和每条处理记录图片均保留来源及历史关系。后台自定义字段平台当前保存
“记录的最新字段值”，不会为每次字段覆盖自动生成独立历史版本；因此页面按来源分组，
不把当前补充图片误标为某一条处理记录的历史图片。
