# 租户档案闭环差距矩阵（2026-07-27）

## 边界

- 租户档案是企业、联系人、合同、房间/车位关系和只读财务结果的聚合视图。
- 房间、车位仍由资产域维护；账单、收款、发票仍由财务域维护。
- 历史合同、账单和发票使用保存时快照，不因当前租户开票资料变更而回写。

## 差距与落地

| 原差距 | 唯一数据来源 | 本次结果 | 自动验证 |
| --- | --- | --- | --- |
| 统一社会信用代码重复、缺少简称/开票资料 | `tenant` | V54 增加简称、开票抬头、纳税人识别号、物业对接人；页面仅保留一个统一社会信用代码 | 编辑保存、数据库回读、浏览器标签计数 |
| 租户目录仅客户端筛选 | `tenant`、`tenant_contact`、`contract_room` | 服务端关键字/状态/分页，返回联系人、有效合同数和房间数 | 无筛选与手机号筛选 HTTP 200 |
| 联系人角色和小程序绑定不完整 | `tenant_contact`、`mobile_user` | 唯一负责人/紧急联系人、手机号唯一、停用保护、换号立即使旧绑定失效并写审计 | 负责人切换、重复手机号、换号收权、跨租户隔离 |
| 空间、合同、账单关系分散 | 合同房间关系、停车绑定、合同、账单 | 五标签聚合；房间/车位含当前与历史，合同含附件，账单只读且保留未明确关联合同记录 | HTTP、数据库、浏览器五标签 |
| 合同附件只有单一文件入口 | `file_upload`、`contract_attachment` | 主合同与补充协议统一受保护上传/下载，替换保留历史关系并审计 | 两附件上传、后台/小程序授权下载、跨租户 404 |
| 负责人和普通员工移动权限边界不清 | 联系人角色、RBAC、服务端 principal | 负责人可看企业合同/账单；普通员工无企业合同/账单权限；客户端 tenantId 不决定范围 | Mock、真实 HTTP 403/404、Node 回归 |
