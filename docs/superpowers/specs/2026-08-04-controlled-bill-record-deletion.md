# 受控账单记录删除

## 目标

为财务账单提供独立于“作废”的记录删除能力，用于清理误录或隔离测试账单。删除是可审计的软删除，不物理擦除正式业务记录，也不改变既有作废、审核、收款、开票和冲红流程。

## 接口

- `POST /api/bills/{id}/record/check`：删除前服务端核验，入参 `{ "version": number }`。
- `DELETE /api/bills/{id}/record`：执行记录删除，入参包含 `version`、非空 `reason` 和与当前账单完全一致的 `confirmBillNumber`。
- 旧 `DELETE /api/bills/{id}` 仅作为“作废账单”的兼容入口，仍要求版本号和真实作废原因，不能用于记录删除。

预检只用于改善交互；正式删除会在事务内重新锁定账单并重复全部校验，不能依赖客户端预检结果绕过并发、权限或业务规则。

## 可删除边界

账单必须同时满足以下条件：

- 来源为人工账单：`source_type = MANUAL`、`source_id IS NULL`、`adjustment_of_bill_id IS NULL`。
- 未收款：`paid_amount = 0`，支付状态为 `UNPAID` 或 `OVERDUE`。
- 未开票：发票状态为 `NOT_INVOICED`。
- 草稿阶段仅允许 `PENDING` 或 `REJECTED`；已经审核的账单还必须具备额外敏感权限。
- 没有任何历史付款、发票、附件、业务来源明细、冲红/补差子账单、计费依据、能耗、会议或其他账单引用。
- 请求版本与数据库当前版本一致，确认编号完全匹配，原因非空且不超过 500 个字符。

校验历史关联时不使用 `deleted = 0` 过滤：曾经存在的付款、发票、附件或来源引用都足以阻止删除，避免通过先软删依赖再删除账单破坏审计链。

## 权限

- 删除草稿记录：精确权限 `bill:delete`。
- 删除已审核记录：除 `bill:delete` 外，还必须有精确权限 `bill:delete-approved`，或当前角色为 `SUPER_ADMIN`。
- `bill:*` 和权限列表中的平台通配符 `*` 都不能替代 `bill:delete-approved`。
- V65 只新增权限目录项，不向任何角色自动分配，保持已有 RBAC 配置不变。
- 管理后台将删除权限放在独立的敏感权限区，普通账单读写权限和批量授权不会隐式勾选或持久化它。

## 数据与审计

成功删除时在同一事务内：

- `bill` 设置 `deleted = 1`、`status = DELETED` 并递增 `version`。
- 所属 `bill_line_item` 设置 `deleted = 1`、`status = REMOVED`。
- 所属 `custom_field_value` 软删除并递增版本。
- `bill_audit_log` 写入 `DELETE_RECORD`，保存删除原因、操作人、删除前完整账单、全部明细列、自定义字段值以及删除后状态。

## 管理后台交互

“作废账单”和“删除账单”是两个独立动作。删除流程依次执行服务端预检、填写删除原因、输入完整账单编号、危险操作二次确认；成功后关闭相关详情、刷新当前列表，并在当前页为空时回到上一页。

## 验证基线

- 后端全量测试、编译和真实 MySQL 删除集成测试必须通过。
- 管理后台权限 resolver、账单交互测试、组件测试、性能基准和生产构建必须通过。
- 小程序全量测试必须保持通过，删除能力不暴露给租户移动端。
- 本地验收必须覆盖 Flyway、真实 HTTP 预检/删除、数据库软删除和审计快照、浏览器 Network/Console 以及隔离数据精确清理。
