# 访客预约审核与门禁二维码闭环

## 目标

访客预约统一由服务端进入待审核队列。物业后台审核通过后上传门禁系统提供的二维码图片，访客再从小程序受保护地查看并出示二维码。二维码只作为门禁凭证附件，不由资产模块或前端生成。

## 状态与操作

| 当前状态 | 允许操作 | 下一状态 |
| --- | --- | --- |
| `PENDING` | 后台通过 | `REGISTERED` |
| `PENDING` | 后台驳回，原因必填 | `REJECTED` |
| `REGISTERED` | 上传或替换二维码 | `REGISTERED` |
| `REGISTERED` | 入场 | `ENTERED` |
| `ENTERED` | 离场 | `LEFT` |
| `PENDING` / `REGISTERED` | 取消 | `CANCELLED` |

未审核预约不得入场；未审核通过、已入场或已结束预约不得上传二维码。

## 数据与接口

Flyway `V58__visitor_review_and_access_qr.sql` 为 `visitor_appointment` 增加审核人、审核时间、审核意见、二维码文件和上传审计字段。

- `PATCH /api/visitors/{id}/approve`：请求体 `{ "reviewRemark": "可选审核意见" }`
- `PATCH /api/visitors/{id}/reject`：请求体 `{ "reviewRemark": "必填驳回原因" }`
- `PUT /api/visitors/{id}/qr-code`：请求体 `{ "fileId": 25 }`
- `GET /api/mobile/visitors`：仅对当前服务端数据范围返回预约；审核通过后返回受保护的 `qrCodeUrl`
- `GET /api/mobile/files/{fileId}`：按当前移动身份、预约归属和文件状态鉴权下载

二维码文件复用统一文件中心。上传草稿必须是当前审核人上传、`INTERNAL`、`visitors` 工作区的图片；绑定后服务端改写为 `VISITOR` 业务附件。替换二维码会停用旧文件，不删除历史文件记录。

## 界面约定

- 后台待审核行显示“通过/驳回”，审核通过行显示“上传二维码”或“更换二维码”。
- 小程序分别展示待审核、审核通过待上传、已驳回及其原因。
- 有二维码时显示居中弹层，二维码容器固定 `320rpx × 320rpx`，支持长按识别或保存。
- 小程序下载器兼容服务端 `/api/mobile/files/*` URL，避免基址已有 `/api` 时重复拼接。
