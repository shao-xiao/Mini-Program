# DHIC 德汇创新中心物业管理系统微信小程序开发规范

本目录：

```text
dehui-property-miniprogram
````

是 DHIC 德汇创新中心物业管理系统的微信小程序工程。

本小程序是物业 SaaS 平台的移动服务入口，不是后台管理端的缩小版，也不是 Demo。主要面向租户、租户员工及经授权的物业服务人员，提供移动端自助服务、业务查询和流程处理能力。

任何 AI Agent、Codex、自动化编码工具，在修改本目录代码前，必须先阅读并遵守：

```text
根目录 AGENTS.md
根目录 ARCHITECTURE.md
根目录 CONTEXT_SUMMARY.md
根目录 MINIPROGRAM_PLAN.md
当前目录 AGENTS.md
```

涉及微信登录、隐私合规、手机号、文件上传、在线支付或租户数据时，必须同时检查现有后端接口和微信公众平台配置。

---

# 一、产品定位

微信小程序服务于移动场景，重点是：

* 租户自助服务
* 账单查询
* 在线缴费
* 发票查看与下载
* 报修和工单进度
* 访客预约
* 停车服务
* 会议预约
* 公告查看
* 租赁与合同信息查询
* 个人资料与账号服务
* 招商获客与房源展示
* 后续 AI 助手能力

小程序必须坚持：

```text
移动任务优先
操作路径短
信息层级清楚
数据权限严格
真实业务闭环
```

禁止把后台管理页面、桌面表格和管理操作直接照搬到小程序。

---

# 二、技术实现原则

具体技术栈、目录结构和语言类型以当前工程代码为准。

修改前必须检查：

```text
app.json
project.config.json
package.json（如存在）
页面目录
组件目录
网络请求封装
登录状态封装
环境配置
分包配置
```

禁止为了统一技术栈而：

* 将现有原生小程序强制迁移到其他框架
* 将 JavaScript 全量迁移为 TypeScript
* 更换现有组件库
* 重写已有网络层
* 重写已有登录体系
* 大规模调整目录结构

新增代码应遵循所在模块的现有语言、命名和组织方式。

---

# 三、开发前置要求

涉及小程序功能时，必须先阅读：

```text
MINIPROGRAM_PLAN.md
```

该文件是小程序产品方向、MVP 范围和阶段计划的主要依据。

开发前必须确认：

1. 功能是否属于当前阶段范围
2. 后端是否已有真实接口
3. 当前用户类型是否允许使用该功能
4. 是否涉及租户数据隔离
5. 是否涉及微信隐私合规
6. 是否需要公众平台配置
7. 是否涉及支付、上传、下载或订阅消息
8. 是否会影响现有审核材料和隐私指引

禁止偏离产品规划自行扩展大功能。

---

# 四、小程序架构原则

推荐结构：

```text
页面层
↓
业务组件层
↓
服务与数据适配层
↓
统一请求封装
↓
后端真实 API
```

页面负责：

* 页面状态
* 用户交互
* 数据展示
* 导航跳转
* 调用业务服务

公共组件负责：

* 空状态
* 加载状态
* 错误状态
* 列表项
* 状态标签
* 筛选弹层
* 上传组件
* 金额显示
* 日期显示
* 权限提示

服务层负责：

* 请求真实接口
* 参数转换
* 返回数据适配
* 统一错误处理
* 登录失效处理

禁止在多个页面重复实现同一套请求、登录、上传或错误处理逻辑。

---

# 五、网络请求规范

所有业务请求必须通过小程序现有统一请求封装。

禁止业务页面直接大量使用：

```js
wx.request()
```

`wx.request` 只能存在于统一网络封装或明确的底层基础设施中。

请求前必须确认：

* 后端真实路径
* HTTP 方法
* 请求参数
* 返回结构
* token 规则
* permission code
* 用户数据范围
* 错误状态

禁止：

* 虚构接口
* 虚构字段
* 使用 mock 数据
* 使用固定假返回值
* 在页面中硬编码生产域名
* 将请求失败伪装成成功
* 使用前端数据代替后端业务结果

---

# 六、API 与环境配置

开发、测试和生产环境必须分离。

API 地址应通过现有环境配置管理，禁止散落在页面中。

禁止硬编码：

```text
localhost
局域网 IP
生产域名
测试域名
```

到具体业务页面。

生产环境必须使用：

```text
HTTPS
```

且相关域名必须配置到微信公众平台合法域名中，包括按实际功能使用的：

* request 合法域名
* uploadFile 合法域名
* downloadFile 合法域名
* web-view 业务域名

禁止依赖开发者工具中的“忽略合法域名校验”作为生产解决方案。

---

# 七、登录与会话规则

微信登录必须使用真实闭环：

```text
wx.login
↓
获取临时 code
↓
发送后端
↓
后端调用微信接口
↓
后端识别或创建用户
↓
后端签发系统 token
```

禁止：

* 客户端伪造 openid
* 客户端自行生成用户身份
* 在客户端保存 session_key
* 将微信 code 当作长期凭证
* 使用固定测试用户绕过登录
* 仅靠前端判断登录有效性

系统 token 的 Header、格式和失效规则必须与后端现有实现一致。

不得擅自增加 `Bearer`，除非后端统一完成兼容变更。

登录失效时，应：

1. 清理失效登录态
2. 避免无限重试
3. 引导重新登录
4. 保留必要的当前页面跳转信息
5. 不泄露服务端异常详情

---

# 八、当前用户权限加载

小程序不得仅依赖本地缓存判断用户权限。

权限和身份应以后端当前真实返回为准。

如果小程序使用角色、菜单或功能权限，应检查现有接口和实现，确保：

```text
用户
↓
角色
↓
permission code
↓
功能入口
↓
后端接口校验
```

本地缓存只能用于减少重复加载，不得作为最终权限真值。

刷新、重新进入小程序或登录状态恢复后，应按现有机制重新获取最新用户信息和权限。

---

# 九、租户和数据隔离规则

租户数据隔离是小程序的核心安全边界。

租户账号只能访问：

* 自己所属租户
* 自己被授权的合同
* 自己的账单
* 自己的发票
* 自己提交或可见的工单
* 自己的访客预约
* 自己的停车、会议和相关服务数据

禁止：

* 通过前端传入任意 tenantId 查询其他租户
* 仅靠隐藏按钮实现租户隔离
* 由客户端决定最终数据范围
* 接口返回全部数据后再由前端筛选
* 信任客户端提交的用户 ID、角色或租户 ID

后端必须根据当前登录身份确定真实数据范围。

发现数据隔离缺口时，不得仅做前端补丁。

---

# 十、RBAC 与功能入口规则

小程序的功能入口和操作按钮必须使用真实权限或真实业务资格判断。

禁止直接硬编码：

```js
if (role === 'TENANT')
```

决定全部业务权限。

如现有系统已使用 permission code，应复用现有 code。

小程序前端负责：

* 隐藏无权限入口
* 隐藏无权限按钮
* 提供清晰提示

后端负责：

* 身份校验
* permission 校验
* 数据范围校验
* 状态流转校验

禁止出现：

* 前端隐藏但接口可直接调用
* 无权限用户通过页面路径进入功能
* 按钮显示与接口权限不一致
* 管理端权限直接复制到租户端
* 为小程序另建一套与后台冲突的假权限

---

# 十一、移动端功能设计原则

小程序不是桌面后台。

页面设计应遵循：

```text
一个页面解决一个主要任务
主要操作优先
次要操作收纳
筛选使用弹层或抽屉
列表适合单手操作
重要状态清晰可见
```

禁止：

* 在小程序中复制宽表格
* 依赖横向滚动查看核心数据
* 堆叠过多统计卡
* 在一个页面放置大量管理按钮
* 使用后台管理端相同的信息密度
* 让用户进行复杂多步骤配置

对于复杂数据：

* 优先列表摘要
* 点击进入详情
* 使用状态标签
* 使用分组信息
* 使用底部操作栏
* 使用筛选弹层
* 对高频任务提供快捷入口

---

# 十二、页面与导航规范

新增页面前必须确认：

* 是否已有同类页面
* 是否应使用公共组件
* 是否应加入分包
* 是否需要登录
* 是否需要权限
* 是否属于 TabBar 页面
* 返回路径是否正确
* 页面参数是否合法

禁止：

* 重复创建同功能页面
* 随意修改 TabBar
* 页面之间通过全局变量传递核心业务数据
* 依赖不可恢复的临时状态
* 无限制堆积页面栈
* 使用不存在的页面路径

涉及页面配置时，必须同步检查：

```text
app.json
分包配置
页面路径
导航标题
隐私接口声明
```

---

# 十三、分包与体积规则

应根据现有项目结构合理使用分包。

适合独立分包的业务包括：

* 租赁
* 停车
* 会议
* 访客
* 工单
* 发票
* 招商
* AI 功能

主包只保留：

* 启动页
* 登录
* 首页
* 我的
* 基础公共能力

禁止：

* 将全部业务放入主包
* 重复打包大型依赖
* 引入仅使用一次的大型库
* 在多个分包复制公共组件
* 为简单功能引入重量级依赖

修改后必须关注微信小程序包体积和分包限制。

---

# 十四、状态管理规则

优先使用：

* 页面状态
* 组件状态
* 现有全局状态方案
* 现有登录状态封装

只有真正跨页面、跨模块共享的数据才放入全局状态。

禁止：

* 为每个页面创建全局 Store
* 在多个位置维护同一用户信息
* 同时使用多套登录状态来源
* 将短期表单数据长期写入缓存
* 将敏感信息永久保存在本地

本地存储必须定义：

* key 名称
* 数据用途
* 失效条件
* 清理时机
* 是否包含敏感数据

---

# 十五、日期与金额规则

日期格式必须遵循项目和后端现有约定。

业务日期统一优先使用：

```text
YYYY-MM-DD
```

禁止依赖不同设备的隐式日期解析。

金额处理必须：

* 明确单位是元还是分
* 禁止浮点数直接参与关键金额计算
* 展示与提交单位保持一致
* 支付金额以服务端订单为准
* 不允许前端自行修改应付金额

涉及账单、支付、滞纳金、退款时，必须确认后端金额口径。

---

# 十六、手机号授权规则

获取手机号必须使用微信当前官方能力和真实后端流程。

流程应为：

```text
用户主动点击
↓
同意手机号授权
↓
小程序获得动态 code
↓
发送后端
↓
后端调用微信接口获取手机号
↓
绑定当前系统用户
```

禁止：

* 启动时强制索要手机号
* 在用户无感知时自动触发授权
* 客户端自行解密敏感数据
* 长期保存一次性动态 code
* 使用测试手机号替代真实流程
* 授权失败后无限弹窗

应明确说明手机号用途。

---

# 十七、隐私合规规则

涉及以下信息时，必须检查隐私保护指引：

* 手机号
* 姓名
* 联系人信息
* 图片
* 发票
* 合同
* 访客信息
* 车牌号
* 位置信息
* 设备相册和摄像头
* 剪贴板
* 文件选择
* 用户生成内容

必须遵循：

* 最小必要原则
* 明确用途
* 用户主动触发
* 授权失败可处理
* 不超范围收集
* 不上传无关数据
* 不在日志打印隐私信息

新增隐私相关能力时，必须同步检查：

* 小程序代码
* 隐私接口声明
* 微信公众平台隐私保护指引
* 用户协议和隐私政策
* 审核材料

禁止为了通过审核填写与实际代码不一致的隐私声明。

---

# 十八、图片与文件上传规则

涉及图片、发票、合同、工单照片等文件时，必须：

* 检查文件类型
* 检查文件大小
* 限制上传数量
* 提供上传进度
* 处理取消和失败
* 防止重复上传
* 使用后端返回的文件标识
* 校验下载权限
* 校验删除权限

禁止：

* 信任客户端文件名
* 将本地临时路径当作永久地址
* 上传后不保存后端文件记录
* 直接拼接服务器路径
* 无权限下载其他租户附件
* 把完整文件内容写入日志

发票上传、租户下载和后台管理端必须使用一致的文件记录体系。

---

# 十九、微信支付规则

涉及微信支付前，必须先阅读相关支付设计和现有后端实现。

正确流程：

```text
用户选择待支付账单
↓
后端校验账单与用户关系
↓
后端创建支付订单
↓
后端调用微信支付下单
↓
后端返回小程序调起支付参数
↓
小程序调用 wx.requestPayment
↓
微信异步通知后端
↓
后端验签并幂等更新账单
↓
小程序主动查询最终支付状态
```

小程序不得：

* 自行计算最终支付金额
* 自行生成支付签名
* 仅凭 `wx.requestPayment` 成功回调确认收款
* 伪造支付成功页面
* 跳过后端订单状态查询
* 重复创建支付订单
* 在前端保存商户密钥
* 在前端保存 APIv3 密钥
* 信任客户端提交的支付结果

支付回调必须由后端完成：

* 验签
* 解密
* 幂等
* 金额核对
* 商户订单核对
* 状态更新
* 操作记录

支付未最终确认时，前端应显示“处理中”，不得显示为已支付。

---

# 二十、订阅消息规则

使用订阅消息必须：

* 由用户主动触发
* 明确消息用途
* 使用真实模板 ID
* 由后端发送
* 记录发送结果
* 处理用户拒绝
* 不重复骚扰用户

禁止：

* 使用虚构模板 ID
* 将模板 ID 硬编码散落在多个页面
* 未经业务触发批量申请订阅
* 在用户拒绝后循环弹窗

---

# 二十一、列表与分页规则

列表页面必须处理：

* 首次加载
* 下拉刷新
* 上拉加载
* 分页结束
* 空状态
* 加载失败
* 重试
* 筛选条件
* 返回页面后的状态恢复

禁止：

* 一次请求全部数据
* 无限制增加列表项
* 重复加载同一页
* 筛选后保留旧分页游标
* 请求失败后展示旧数据但不提示
* 前端对全量数据做租户权限过滤

---

# 二十二、表单规范

表单提交必须：

* 校验必填字段
* 校验格式
* 防止重复点击
* 提供提交中状态
* 处理失败信息
* 成功后刷新真实数据
* 避免重复创建业务记录

禁止：

* 只做前端校验
* 提交成功前提前关闭页面
* 用提示信息掩盖接口失败
* 静默吞掉后端业务错误
* 自动填充未经确认的关键业务值

---

# 二十三、错误处理与降级

接口失败时，应区分：

* 网络异常
* 登录失效
* 无权限
* 参数错误
* 业务状态冲突
* 服务端异常
* 微信能力调用失败

禁止所有错误统一提示：

```text
请求失败
```

无权限时应：

* 隐藏不适用入口
* 保留明确提示
* 不循环跳转
* 不自动放开权限

单个非核心模块失败时，不应拖垮整个首页。

---

# 二十四、性能规则

必须关注：

* 首屏加载时间
* 分包体积
* 图片大小
* 重复请求
* 列表渲染
* setData 数据量
* 不必要的深层对象更新
* 页面切换缓存
* 组件重复创建

禁止：

* 一次 setData 大量无关数据
* 在 WXML 中执行复杂计算
* 高频定时器不清理
* 页面卸载后继续请求
* 未压缩的大图片直接上传
* 重复下载同一静态资源

---

# 二十五、安全规则

禁止在小程序代码中存放：

* 数据库密码
* 服务器密码
* 微信支付私钥
* APIv3 密钥
* AppSecret
* 永久 access_token
* 生产环境管理凭证
* 完整用户 token 日志

前端代码中的 `appid` 并不等同于密钥，但仍应通过现有项目配置统一维护。

禁止信任客户端提交的：

* userId
* tenantId
* role
* permission

# 二十七、AI 能力规则

小程序接入 AI 功能时：

* 必须使用真实后端 AI 接口
* 不在客户端直接保存 AI API Key
* 不允许客户端直接调用第三方大模型密钥
* 需要进行用户数据范围校验
* 不向模型发送无关隐私信息

* 高风险业务不得由 AI 自动执行
* AI 接口失败不能拖垮主要业务

禁止用固定文本伪装 AI 分析结果。
